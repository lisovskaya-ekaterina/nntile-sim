# Исходный код NNTile Simulator

В каталоге `src/` находится исходный код симулятора выполнения вычислительных задач NNTile с моделированием памяти GPU и передач данных между CPU и GPU.

Основная цель проекта — исследование алгоритмов планирования вычислений, загрузки, выгрузки и вытеснения данных для минимизации общего времени выполнения (makespan).

## Структура проекта

```text
src/
└── nntile_sim/
    ├── __init__.py
    ├── model.py
    ├── parser.py
    ├── chunks.py

    ├── plotting.py
    └── core/
        ├── engine.py
        ├── exact_small.py
        ├── global_planner.py
        └── scheduling/
```

## Глобальный планировщик

Основная разрабатываемая функциональность находится в:

- `core/global_planner.py`
- `core/scheduling/`

Планировщик формирует расписание операций с учётом зависимостей вычислительных задач, ограниченного объёма памяти GPU и пропускной способности каналов передачи данных.

Рассматриваются три независимых исполнительных ресурса:

1. **Compute** — выполнение вычислительных задач.
2. **H2D** — передача данных из памяти CPU в память GPU.
3. **D2H** — передача данных из памяти GPU в память CPU.

Планировщик также управляет размещением и освобождением данных в памяти GPU.

Основные принципы модели:

- Длительности вычислительных задач известны из трассы.
- Длительность передачи определяется размером данных и пропускной способностью канала.
- Память GPU имеет ограниченную общую ёмкость.
- Данные, используемые вычислительной задачей, должны находиться в GPU на протяжении всего её выполнения.
- Изменённые данные требуют сохранения актуальной версии, если она понадобится после вытеснения.
- Чистые данные, имеющие актуальную копию в CPU, могут вытесняться без обратной передачи.

**Цель оптимизации — минимизация makespan**, то есть времени завершения последней необходимой операции расписания.

## Внутренняя структура планировщика

Каталог `core/scheduling/` разделяет задачи планирования на отдельные компоненты:

| Модуль | Назначение |
|---|---|
| `planner.py` | Построение расписания |
| `baseline.py` | Базовые алгоритмы и стратегии |
| `bounds.py` | Расчёт оценок нижней границы времени выполнения |
| `optimization.py` | Оптимизация расписания |
| `packing.py` | Размещение данных с учётом ограничений памяти |
| `residency.py` | Управление нахождением данных в GPU |
| `residency_search.py` | Поиск вариантов размещения и вытеснения данных |
| `prefetch_cleanup.py` | Обработка предварительных загрузок |
| `writeback.py` | Обработка сохранения изменённых данных |

## Разработка

Новые алгоритмы глобального планирования следует размещать в `core/scheduling/`, сохраняя разделение ответственности между модулями.

После изменения логики планирования необходимо запускать тесты из корня репозитория:

```bash
python -m pytest -q
```

Текущий результат контрольного запуска на момент подготовки документации: **106 passed, 2 xfailed, 19 subtests passed**.

Каталоги `__pycache__/` и `*.egg-info/` создаются инструментами Python автоматически, не являются исходным кодом и не должны включаться в Git.
