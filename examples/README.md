# Примеры трасс NNTile

Каталог `examples/` содержит трассы вычислительных задач NNTile, используемые для тестирования и исследования алгоритмов глобального планирования вычислений и управления памятью GPU.

## 1. Содержимое каталога

| Файл | Описание |
|---|---|
| `tasks_mbs1.rec` | Трасса с MBS = 1, содержащая четыре основные группы вычислительных задач |
| `tasks_mbs4.rec` | Трасса с MBS = 4, содержащая одну основную группу вычислительных задач |

Обе трассы описывают вычислительные задачи, их зависимости, длительности и обращения к данным (хэндлам).

## 2. Почему в MBS = 1 четыре подграфа

В рассматриваемых экспериментах MBS, предположительно, обозначает размер микробатча (*microbatch size*), а не количество микробатчей.

При одинаковом общем размере обрабатываемого батча:

- **MBS = 1:** данные обрабатываются четырьмя микробатчами, что соответствует четырём основным группам вычислительных задач.
- **MBS = 4:** данные обрабатываются одним микробатчем, что соответствует одной основной группе вычислительных задач.

Такое объяснение согласуется с группировкой задач в трассах. Однако точное значение MBS и параметры генерации необходимо подтвердить по исходной конфигурации эксперимента.

### Структура вычислительных задач

Для `tasks_mbs1.rec`:

| Группа итераций | Количество задач |
|---|---:|
| `(0,)` | 198 |
| `(0, 0)` | 1 268 |
| `(0, 1)` | 1 268 |
| `(0, 2)` | 1 268 |
| `(0, 3)` | 1 268 |
| `(0, 2147483647)` | 197 |
| Без группы (`None`) | 17 |
| **Всего** | **5 484** |

Для `tasks_mbs4.rec`:

| Группа итераций | Количество задач |
|---|---:|
| `(0,)` | 198 |
| `(0, 0)` | 5 057 |
| `(0, 2147483647)` | 197 |
| **Всего** | **5 452** |

Группы `(0,)` и `(0, 2147483647)` присутствуют в обеих трассах. Их точную роль следует определять по логике генерации трасс.

Наличие четырёх групп `(0, 0)`–`(0, 3)` не означает, что они полностью независимы. Между задачами могут существовать зависимости и общие данные.

## 3. Сравнение трасс

| Характеристика | MBS = 1 | MBS = 4 |
|---|---:|---:|
| Вычислительных задач | 5 484 | 5 452 |
| Уникальных хэндлов | 1 371 | 2 988 |
| Основных групп вычислений | 4 | 1 |
| Обращений на чтение (`R`) | 6 600 | 6 573 |
| Обращений на запись (`W`) | 3 005 | 2 979 |
| Обращений `RW` | 849 | 846 |
| Обращений `RWC` | 2 024 | 2 021 |

Количество вычислительных задач и обращений к данным в двух трассах близко, однако число уникальных хэндлов отличается более чем вдвое.

Это означает, что трассы представляют разные сценарии работы с данными, даже при близком количестве вычислений.

### Почему различие важно

**MBS = 1** позволяет исследовать планирование нескольких групп вычислений:

- выбор порядка выполнения готовых задач;
- возможное перекрытие вычислений разных групп;
- повторное использование данных;
- предварительную загрузку данных для следующих задач;
- управление памятью при переключении между группами.

**MBS = 4** позволяет исследовать планирование одного более крупного вычислительного графа:

- работу с большим количеством уникальных хэндлов;
- влияние объёма доступной GPU-памяти;
- частоту вытеснения и повторной загрузки данных;
- эффективность предварительных загрузок;
- выбор порядка вычислений внутри графа.

Это исследовательские гипотезы, которые необходимо проверять экспериментально, а не заранее установленные преимущества какой-либо конфигурации.

## 4. Для чего используются трассы

На этих данных исследуются:

- Планирование вычислительных задач с учётом зависимостей.
- Предварительная загрузка данных из CPU в GPU (H2D).
- Сохранение изменённых данных из GPU в CPU (D2H).
- Вытеснение и повторное использование данных в ограниченной памяти GPU.
- Влияние размера чанков и доступной памяти на эффективность расписания.
- Сравнение глобального планировщика с базовыми стратегиями LRU и Belady.

Основная метрика — **makespan**, общее время выполнения расписания.

Дополнительно анализируются простой Compute, загрузка каналов передачи данных, объём перемещённых данных и пиковое использование памяти GPU.

## 5. Просмотр статистики трасс

Из корня проекта:

```bash
nntile-trace examples/tasks_mbs1.rec
nntile-trace examples/tasks_mbs4.rec
```

Команда выводит количество вычислительных задач, уникальных хэндлов, распределение по итерациям и режимы доступа к данным.

## 6. Запуск сравнительного эксперимента

Пример запуска для `tasks_mbs1.rec`:

```bash
python scripts/benchmark_nntile_graph.py examples/tasks_mbs1.rec \
  --capacities-mib 768 1024 1536 \
  --h2d-gbps 12 \
  --d2h-gbps 12 \
  --chunk-mib 1 \
  --output results/global_comparison/benchmark.csv
```

Эксперимент сравнивает три стратегии:

1. `lru-demand` — загрузка по требованию с вытеснением LRU.
2. `belady-demand` — загрузка по требованию с вытеснением Belady.
3. `global-planner` — глобальное планирование вычислений и передач данных.

Результаты сохраняются в CSV-файлы для дальнейшего анализа.

## 7. Примечания

- Исходные трассы следует сохранять без изменений, чтобы результаты экспериментов оставались воспроизводимыми.
- Результаты запусков сохраняются в `results/`, а не в `examples/`.
- При добавлении новых трасс необходимо указывать их происхождение, параметры и назначение.
- Подробное описание исследовательских скриптов находится в `scripts/README.md`.
- Подробное описание глобального алгоритма находится в `ALGORITHM.md` в корне проекта.
